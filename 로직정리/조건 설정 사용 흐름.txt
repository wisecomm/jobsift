================================================================================
조건 설정(criteria / aiSettings / siteSettings) 구조별 정리 (kr-job-finder)
================================================================================

수정·확인 시 보는 파일
- UI 입력        : src/page/SettingsView.tsx, src/page/SitesView.tsx, src/page/Header.tsx
- 조건 스키마    : src/engine/criteria.ts, src/ai/settings.ts, src/engine/siteSettings.ts
- 규칙 게이트    : src/engine/evaluate.ts (RULE_GATES)
- URL/AI 프롬프트: src/engine/buildSearchUrl.ts, src/ai/prompt.ts
- AI 제공자 호출 : src/ai/provider.ts -> src/ai/gemini.ts, src/ai/exaone.ts, src/ai/parseScores.ts
- 변경 재적용    : src/engine/applyCriteriaChange.ts, src/background/service-worker.ts


--------------------------------------------------------------------------------
1. 조건을 구조별(역할별)로 모은 표
--------------------------------------------------------------------------------

  [그룹 A: 수집 범위 조건] -> 어디서/몇 건까지 긁어올지 결정
  ├─ keywords    : 사이트 검색 URL의 {keyword} (collect.ts / buildSearchUrl.ts)
  ├─ career      : 사이트별 검색 쿼리 파라미터 변환 (adapter.search.params)
  └─ maxItems    : 사이트 설정(SitesView / siteSettings)의 키워드당 최대 수집 개수 (기본값 2,000건)
                   * 이미 마감된 공고(deadline < 현재 시각)는 maxItems 개수에서 제외
                   * 초과 시 collectState.resume(nextPage, maxCollectedAt) 저장 후 중단,
                     [계속 수집] 버튼으로 멈춘 다음 페이지부터 이어서 수집 가능
                   * 최초 수집(lastCollectedAt 없음)은 최근 7일(INITIAL_LOOKBACK_DAYS=7) 이내만 수집,
                     이후 실행부터는 lastCollectedAt 기준으로 증분 수집

  [그룹 B: 규칙 필터 조건 (RULE_GATES)] -> src/engine/evaluate.ts 한 곳에서 관리
  ├─ (deadline)  마감일 경과 여부      -> expired
  ├─ (keyword)   keywords 미포함       -> keywordMismatch (AI OFF일 때만 적용)
  ├─ (location)  locations 시/도 매칭  -> location (미설정·공고지역 없으면 통과)
  └─ (career)    career 신입/경력 상충 -> career

  [그룹 C: AI 채점 조건] -> 선택된 기본 제공자(provider)에 apiKey가 있을 때만 동작 (aiEnabled)
  ├─ provider         : 기본 AI 제공자 콤보 선택
  │                     - gemini : Google Gemini (기본값, 기본 모델 gemini-3.5-flash-lite)
  │                     - exaone : LG EXAONE (K-EXAONE 2.5, 기본 모델 k-exaone_v2.5)
  ├─ keysByProvider   : 제공자(gemini / exaone)별 API 키를 각각 독립 저장·삭제
  ├─ modelsByProvider : 제공자별 모델명을 각각 독립 저장
  ├─ description      : "내가 원하는 일"
  │                     - 작성 시: 원문 그대로 프롬프트의 `## 구직자가 원하는 일`에 전달
  │                     - 비어 있을 시: keywords / career로 문장을 자동 조합해 전달
  └─ minScore         : 합격 커트라인 (0~100, 기본 60 -> 이상 postings, 미만 discards)


--------------------------------------------------------------------------------
2. 조건 변경 저장 시 재처리 (saveSettings / deleteAiKey -> commitSettings -> applyCriteriaChange)
--------------------------------------------------------------------------------

  저장 요청 (saveSettings / deleteAiKey)
       │
       ▼
  [1] chrome.storage.local에 새 criteria / aiSettings 즉시 기록
  [2] 진행 중인 수집·채점 작업이 있으면 즉시 중단 (activeAbort.abort())
       │
       ▼
  <settingsChanged() 변경 여부 확인>
   ├─ 규칙 필드(A·B) 변경, AI ON/OFF 전환, 기본 제공자(provider) 전환,
   │  (AI ON일 때) description / minScore / model 변경
   └─ 변경 없으면 추가 재분류 없이 종료
       │
       ▼ (변경 시: applyCriteriaChange)
  discards + collectState 초기화 (다음 수집 때 새 조건으로 재스캔)
       │
       ▼
  기존 공고 재평가 (saved / applied / dismissed / expired / 메모 작성 공고는 보호)
   ├─ 규칙 탈락           ─▶ discards로 이동 (alsoOn 출처 포함)
   ├─ 규칙 통과 & AI ON   ─▶ pending으로 이동 (새 기준 재채점 대기)
   └─ 규칙 통과 & AI OFF  ─▶ postings에 status='new', score=null 로 유지/복원
